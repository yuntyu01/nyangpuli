# 냥풀이 모바일 (초기 개발 화면)

Expo SDK 58, React Native 0.88, TypeScript 6을 사용합니다. SDK 58 공식 `expo-template-blank-typescript`의 React/React Native 버전과 Expo 패키지에 포함된 호환 버전을 기준으로 고정했습니다. `package-lock.json`으로 설치합니다. Node 24를 사용하세요.

```sh
cd apps/mobile
npm ci
npm test
npm run typecheck
# 앱에서 접근 가능한 백엔드 HTTPS 주소를 지정합니다. 비밀값을 여기에 넣지 마세요.
EXPO_PUBLIC_API_URL=https://your-development-api.example npm run android
# macOS + Xcode에서:
EXPO_PUBLIC_API_URL=https://your-development-api.example npm run ios
# 개발 빌드를 설치한 뒤 Metro 실행:
EXPO_PUBLIC_API_URL=https://your-development-api.example npm start
```

`expo run:android`에는 Android SDK와 에뮬레이터 또는 기기가 필요하고 `expo run:ios`에는 macOS/Xcode가 필요합니다. 개발 빌드를 사용하며 Expo Go만으로 검증했다고 주장하지 않습니다. 기기에서 `localhost`는 서버가 아니라 기기 자신입니다. TLS로 보호된 개발 서버를 사용하세요. 현재 설정 화면의 토큰 입력은 개발용 연구 서버와의 임시 연결 수단이며, 앱에 내장하거나 공개 환경변수에 넣지 않습니다. 토큰은 Expo SecureStore에 저장하고 로그에 출력하지 않습니다. 앱은 서버에서 검증한 계정만 사용하며 사용자 ID를 보내지 않습니다.

홈은 제공된 이미지의 라일락·핑크 카드, 하단 내비게이션과 글자 배치를 참고했습니다. 제공 이미지의 고양이 그래픽은 별도 이미지 파일이 없어 임시 이모지로 표시합니다. 화면 전체를 이미지로 사용하지 않습니다. 출생 정보는 서버 계정에 저장하고 이 기기에는 프로필 식별자만 보관합니다. 오늘 날짜는 기기의 현재 시간대를 기본으로 하며 사용자가 확인한 시간대를 서버에 전달합니다. 양력 또는 음력 평달·윤달을 선택할 수 있으며 음력 날짜가 실제로 존재하는지는 풀이 요청 때 엔진에서 검증합니다. 출생시간을 모르면 풀이를 요청하지 않습니다.

기존 API에 연결된 기능은 사주·오늘의 운세·궁합·상담 요약 요청, 보관함 조회, 상세 권한 확인, 기억 조회·직접 추가·개별 수정·이력 조회·삭제, 한 장·세 장 타로 선택입니다. 모델 미설정 시 결과를 꾸며내지 않고 오류를 표시합니다. 응답이 불명확한 요청은 자동 재생성하지 않고 보관함 확인을 안내합니다. 계정 삭제 화면은 PostgreSQL 전용 서버에서만 동작하며 외부 서비스·백업에 보관된 사본은 별도 처리해야 합니다. 실제 구매와 운영용 복구 계정 연결은 아직 구현되지 않았습니다. 이 화면은 운영용 계정·결제 기능으로 배포할 수 없습니다.

검증: Node 단위 테스트 41건(날짜·상담 입력·서버 URL·타로·기억·개발 구매·계정·프로필·일운 권한 계약 검증), `tsc --noEmit`, Android용 Metro 번들 생성과 임시 디렉터리에서 Android 네이티브 프로젝트 생성(prebuild)이 통과했습니다. SDK 패키지 버전은 Expo의 로컬 호환 목록으로 검사했습니다(오프라인 검사). Android/iOS 네이티브 빌드와 실기기 화면·접근성·구매 흐름은 미검증입니다. 빌드 및 실제 기기 시험 후 긴 한국어, 글자 확대, 키보드, 작은 화면, 스크린 리더를 다시 확인해야 합니다.

사용자 연결을 변경하거나 해제하면 앱 메모리의 출생 정보, 질문, 기억 및 결과도 비웁니다. 보관함·기억 조회 실패는 빈 결과로 표시하지 않으며 다시 불러올 수 있습니다. 모든 빌드는 HTTPS 서버를 사용하며 개발 빌드에서만 명시된 루프백 HTTP를 허용합니다. 인증된 요청과 계정 요청은 redirect:error를 설정합니다. 이 설정의 실제 React Native 네이티브 동작은 기기에서 검증하지 않았습니다. 앱의 실제 화면 접근성과 안전 영역은 기기에서 추가 검증해야 합니다.

타로는 서버가 고정한 78개 위치에서 한 장 또는 세 장을 선택합니다. 선택된 카드와 정역방향은 서버에 저장되며, 기기 보안 저장소에는 현재 세션 ID만 보관해 재접속 시 조회합니다. 선택 요청의 응답이 유실되면 재선택하지 않고 서버 상태를 확인합니다. 시작 요청의 응답이 유실된 경우 세션 ID를 받지 못하므로 새로 시작하면 별도의 세션이 만들어질 수 있습니다. 현재 서버에는 세션 목록 조회가 없어 이 기기에서 새로 뽑기 또는 연결 해제 시 이전 세션을 다시 찾을 수 없습니다. 카드별 원문 의미와 저장된 카드·질문에 대한 무료 요약을 제공합니다. 상세는 해당 풀이의 서버 권한이 확인된 경우에만 요청할 수 있습니다. 실제 구매는 미지원입니다. 모바일 실제 기기와 PostgreSQL을 함께 연결한 타로 화면 검증은 실행하지 않았습니다.

기억의 개별 수정·이력·삭제는 PostgreSQL 서버에서만 지원합니다. 사용자가 직접 사건 시각을 UTC로 입력하며 임의의 시각을 기본값으로 넣지 않습니다. 정정 시 원래 출처 ID와 사건 시각을 보존하고, 변경 응답이 불확실하면 자동 반복 없이 목록을 다시 확인합니다. 모바일 기기와 PostgreSQL을 연결한 전체 기억 화면 흐름은 미검증입니다.

개발 전용 모의 구매 UI는 개발 빌드와 `EXPO_PUBLIC_ENABLE_TEST_PURCHASES=1`을 함께 설정한 경우에만 표시됩니다. 백엔드는 PostgreSQL 및 `NYANG_ENV=development`와 `--test-unlocks`가 필요합니다. 실제 과금, 스토어 영수증, 가격, 스토어 복원과 관계없는 시뮬레이션이며 서버 조회로 권한이 확인된 경우에만 상세 요청을 제공합니다. 설정의 테스트 기록은 서버의 모의 거래 목록입니다. 요청 결과가 불확실하면 자동 재요청하지 않고 해당 풀이의 서버 권한을 다시 확인합니다. 모의 구매 화면의 실제 기기·DB 통합 흐름과 실제 StoreKit/Play Billing은 미검증입니다.

개발 계정 화면은 개발 빌드에서 `EXPO_PUBLIC_ENABLE_DEV_ACCOUNTS=1`을 설정할 때만 나타나며 PostgreSQL 개발 서버가 필요합니다. 게스트 생성, 게스트에 로그인 정보 연결, 개발 사용자 등록·로그인·세션 로그아웃을 지원합니다. 세션은 SecureStore에 저장합니다. 연결하지 않은 게스트의 토큰을 잃거나 로그아웃하면 기록 복구가 불가능하며, 비밀번호 재설정도 지원하지 않습니다. 개발 계정은 운영 인증으로 사용할 수 없습니다. 계정 암호는 HTTPS 또는 개발 기기의 명시적 루프백 서버로만 전송합니다. 실제 기기에서 계정 연결과 재로그인 흐름은 검증하지 않았습니다.

프로필 생성과 정정은 PostgreSQL API에 연결되어 있으며 정정 시 서버 버전을 사용합니다. 기기 변경 또는 계정 전환 후 서버 목록에서 본인 정보를 직접 선택할 수 있습니다. 목록에는 본인과 상대를 구분할 이름이 없으므로 자동 선택하지 않습니다. 현재 시간대와 출생 시간대가 다른 일운은 엔진의 계산 제한으로 제공하지 않습니다. 모바일 기기에서 DB 저장·재접속·일운 요청은 미검증입니다.

일운 API는 무료 요약만 반환하므로 결과 ID로 풀이를 별도 조회해 현재 상세 열람 권한을 확인합니다. 조회 실패 시 요약은 보여 주되 상세 구매나 열람을 허용하지 않고 다시 확인할 수 있게 표시합니다.

사주·궁합·상담의 무료 요약은 PostgreSQL 비동기 작업 API를 사용합니다. 요청 전에 임의의 요청 키만 기기 보안 저장소에 저장하며 원문 사연은 저장하지 않습니다. 앱을 다시 연 뒤 같은 계정으로 작업 상태를 조회할 수 있습니다. 응답 유실·미확정·서버 재시작 후 중단 상태를 자동 재호출하지 않습니다. 서버와 계정별로 분리해 보관하므로 다른 계정으로 전환하거나 로그아웃해도 이전 계정의 키는 유지되며 같은 계정으로 재로그인하면 복구됩니다. 계정을 삭제할 때 해당 키를 지웁니다. JSON 실험 서버에서는 이 작업 API가 제공되지 않습니다. 타로 요약은 서버가 세션별로 동일한 요청 키를 사용하므로 응답 유실 시 같은 카드의 기존 요청을 확인할 수 있습니다. 해당 API와 모바일의 실제 기기 통합 흐름은 미검증입니다.

이전 버전에서 계정 소유자가 기록되지 않은 요청 키가 발견되면 새 생성을 막고, 사용자가 이전 계정을 확인한 뒤 서버 상태를 조회하거나 키 삭제를 명시적으로 선택하도록 합니다. 서버 조회가 실패하거나 현재 계정에 다른 작업이 있으면 이전 키는 유지됩니다. 계정 삭제 요청 전에는 기기 정리용 해시를 저장합니다. 응답이 유실되면 서버 삭제를 성공으로 추정하지 않으며, 재실행 후 사용자가 서버 삭제 여부와 별개로 기기의 연결 정보만 지울 수 있습니다.
