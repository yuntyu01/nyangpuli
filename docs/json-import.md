# 기존 JSON 데이터 이관

`cmd/nyangpuli-import`는 기존 단일 프로세스 JSON 기억과 풀이 스냅샷을 명시적인 계정별 매핑에 따라 PostgreSQL에 이관한다. 원본 파일을 수정하거나 삭제하지 않는다. 이전 서버는 이관 전 반드시 중지한다. JSON 저장소에는 프로세스 간 잠금이 없으므로 실행 중에 원본을 쓰면 안전한 이관을 보장할 수 없다. 원본과 DB의 보호된 백업을 확보하고 복구 절차를 먼저 확인한다. 원본에 개인정보가 들어 있으므로 파일, 매핑, 백업을 Git이나 로그에 남기지 않는다.

1. PostgreSQL 마이그레이션 012까지 적용하고, 대상 계정을 미리 만든다. DB 모드의 서버는 시작할 때 마이그레이션을 실행한다. 원래 JSON 경로를 덮지 않도록 기존 파일이 없는 별도 `--memory`, `--readings` 경로로 개발 서버를 시작하고 대상 계정을 만든 뒤 서버를 중지할 수 있다. 인증된 `GET /v1/auth/me`로 대상 계정 ID를 확인한다. 서버 기본 설정은 운영용이 아니다.
2. 보호된 위치에 JSON 객체 형식의 매핑 파일을 만든다. 예: `{"legacy-user":"target-account-id"}`. 선택한 모든 원본 사용자에 대해 정확히 하나의 기존 활성 계정이 필요하며, 여러 원본 사용자를 하나의 계정으로 합칠 수 없다. 이관 대상 계정에 기억·풀이 작업이나 기억 삭제 이력이 이미 있으면 병합하지 않고 거부한다.
3. `DATABASE_URL`을 안전하게 설정하고 저장소 루트에서 다음을 실행한다. `--memory` 또는 `--readings`는 해당 원본이 없을 때 생략한다. 아래 경로는 예시다.

```sh
go run ./cmd/nyangpuli-import --memory /secure/memory.json --readings /secure/readings.json --mapping /secure/mapping.json
# dry-run에서 수와 오류를 확인한 뒤 실제 반영:
go run ./cmd/nyangpuli-import --memory /secure/memory.json --readings /secure/readings.json --mapping /secure/mapping.json --apply
```

기본 dry-run은 동일한 대상 검사와 DB 쓰기를 트랜잭션에서 수행한 뒤 롤백한다. 결과는 사용자·기억·풀이 개수와 재이관 여부만 표시하며 사연, 매핑, 토큰, 원본 내용은 출력하지 않는다. 실제 반영은 하나의 트랜잭션으로 적용하며 오류 시 전체 롤백한다. 동일 파일의 해시와 매핑을 기록해 동일 요청을 재실행하면 아무것도 추가하지 않는다. 동일 파일을 다른 계정 매핑으로 이관하거나 일부 파일만 이미 이관된 묶음은 거부한다. 원본 파일 변경도 이관 중 검사하지만 외부 프로세스와의 경쟁을 막지는 못하므로 반드시 이전 서버를 중지해야 한다. 정확히 읽어 들인 바이트를 메모리에서 검증하며 임시 사본을 만들지 않는다. 같은 기억 키에 사건 시각이 동일한 레코드가 있으면 JSON과 DB의 현재값 정렬 차이를 피하려고 이관을 거부한다.

기억의 ID, 사건·저장 시각, 원문 사실과 정정 관계를 보존한다. PostgreSQL timestamp 자체는 마이크로초 정밀도이므로 JSON 원본의 저장 시각은 별도 필드에 나노초 정밀도로 보존하고 조회에 반영한다. 풀이의 ID, 요약, 상세, 고정 근거, 사용량, 원본 상태와 키를 보존한다. 출처가 기존의 `test_only_not_payment`인 개발용 해제만 개발용 권한으로 옮기며, 서버에서 테스트 해제를 명시적으로 허용하지 않으면 상세가 노출되지 않는다. 실제 스토어 구매를 추론하거나 만들어내지 않는다. 처리 도중 중단됐거나 결과가 불확실한 작업은 불확정으로 보관하고 모델을 자동 재호출하지 않는다. 기존 JSON의 명시적 실패는 DB의 실패 상태로 보관하며 자동 재시도하지 않는다. 상담 풀이 스냅샷은 보수적으로 기억에 의존한 것으로 취급해 이후 기억 변경 시 무효화한다.

JSON 파일이 원래 경로에 그대로 남아 있으면 DB 모드 서버는 실수로 무시하는 것을 막기 위해 시작을 거부한다. 이관 결과와 백업을 확인한 뒤 원본을 삭제하지 말고, DB 서버를 시작할 때 기존 파일이 없는 별도의 `--memory`, `--readings` 경로를 명시한다. 실제 운영 권한, 외부 Mem0, 파일 첨부, 스토어 거래 및 백업 내 데이터는 이 명령으로 이관되지 않는다. 운영 데이터나 실결제 권한을 수동으로 추정해 옮기지 않는다.
