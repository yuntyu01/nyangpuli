# 개발용 계정 연결과 로그인

PostgreSQL 모드에서 `POST /v1/auth/guest`는 새 게스트와 세션을 만든다. 세션은 앱의 플랫폼 보안 저장소에 보관한다. 기기에서 게스트 토큰을 잃으면 연결 전 기록을 복구할 수 없다. 로그인 정보를 연결하려면 인증된 `POST /v1/auth/link`에 `username`과 `password`를 전달한다. 이후 `POST /v1/auth/login`으로 새 세션을 발급받아 같은 계정에 접근할 수 있다. `POST /v1/auth/register`는 새 연결 계정을 만들고, 인증된 `POST /v1/auth/logout`은 현재 세션만 폐기한다. 계정 ID는 요청 본문이 아닌 검증된 토큰으로 결정한다.

사용자명은 영문 소문자·숫자·점·밑줄·하이픈으로 3~64자이며 처음은 영문 또는 숫자여야 한다. 입력 영문 대문자는 소문자로 정규화한다. 비밀번호는 UTF-8 기준 12~128바이트다. 비밀번호는 랜덤 16바이트 salt와 Argon2id(반복 3회, 64 MiB, 병렬도 1, 32바이트) 해시만 저장한다. 토큰은 256비트 난수를 사용하며 서버는 SHA-256 해시만 보관하고 30일 후 만료한다. 계정당 로그인 정보는 하나이며 다른 사용자명이나 계정으로 덮어쓰거나 합치지 않는다. 다섯 번 실패하면 15분 동안 로그인할 수 없다. 계정 삭제는 자격 증명과 세션도 제거한다.

이는 개발 기반이다. 비밀번호 분실 시 재설정할 검증된 이메일 등 외부 전달 수단, 비밀번호 변경, 전체 기기 세션 관리, 분산·IP 단위 공격 방지와 운영 인증 보안 검토는 아직 없다. 따라서 비밀번호를 분실하면 로그인 정보를 복구할 수 없다. 외부 메일은 발송하지 않는다. TLS 종단이 없는 현재 로컬 개발 API를 공용 네트워크에 노출하지 말아야 하며 운영 모드는 계속 차단된다. 실제 운영 전에는 TLS, 비밀번호 및 세션 정책과 abuse 방어를 별도로 검증해야 한다.

현재 사용자명 중복 여부는 가입·연결 응답에서 드러날 수 있고, 고정 계정 잠금은 제3자가 반복 실패를 일으켜 계정 접근을 방해할 수 있다. 게스트 계정 생성도 요청 단위 제한이 없다. 분산·네트워크 단위 제한과 복구 정책을 갖추기 전에는 이 인증 API를 운영 환경이나 공용 인터넷에 노출하지 않는다.
