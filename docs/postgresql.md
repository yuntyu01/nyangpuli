# PostgreSQL 기반 (진행 중)

`DATABASE_URL`을 설정하면 서버는 시작 시 PostgreSQL에 연결해 `internal/persistence/migrations`를 순서대로 트랜잭션 안에서 적용하고 DB 세션으로 인증한다. 동시 시작은 PostgreSQL advisory lock으로 직렬화한다. 토큰은 난수 256비트이며 SHA-256 해시만 보관한다. 만료, 폐기 및 계정 삭제 상태를 조회한다. 인증 시 본문의 사용자 ID는 사용하지 않는다.

**아직 전체 전환이 아니다.** DB 모드에서 명시적 개인 기억은 PostgreSQL에 저장하고, 풀이 서비스는 아직 JSON 파일을 사용한다. 기존 JSON 기억 파일이 있으면 자동 덮어쓰기나 누락을 피하기 위해 DB 모드 시작을 거부한다. 안전한 이관 도구는 아직 필요하다. 계정 복구/로그인, JSON 이관, 구매 검증, 작업 복구, 전체 개인정보 삭제 및 이들 저장소의 DB 연결이 필요하다. DB 세션 발급은 신뢰할 수 있는 인증 제공자 연동 후에만 호출해야 한다. 정적 토큰은 DB 미설정 로컬 실험 서버에서만 쓰며 운영 모드는 준비되기 전까지 실행이 차단된다.

격리된 테스트 DB를 준비한 후 `NYANG_TEST_DATABASE_URL=postgres://... go test -v ./internal/persistence`를 실행한다. 테스트는 마이그레이션 동시 적용과 재호출, 사용자 조건 조회, 세션 재연결 및 폐기를 검증한다. 같은 URL로 `go test -v ./internal/memory`를 실행하면 개인 기억의 동시 중복 입력, 사용자 격리, 과거 사건 및 삭제를 실제 PostgreSQL에서 검증한다. URL 미설정 시 통합 테스트는 건너뛴다. 이 테스트의 별도 DB 연결은 PostgreSQL 서버 프로세스 재시작 테스트가 아니다.

백업과 복원은 민감정보를 포함하므로 암호화된 백업과 접근 통제, 복원 검증 및 보존 기간 정책을 마련해야 한다. 아직 운영 배포용 백업·복구 절차는 검증되지 않았다.
