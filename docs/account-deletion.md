# 계정 삭제

`DELETE /v1/account`는 인증 세션의 사용자만 대상으로 하며 요청 본문의 사용자 식별자를 사용하지 않습니다. PostgreSQL 인증과 기억·풀이 모두 PostgreSQL을 사용하는 설정에서만 허용합니다. JSON 파일 모드나 Mem0 원격 기억이 활성화된 서버에서는 범위를 보장할 수 없어 503으로 거부합니다. 앱은 삭제 전 확인을 요청하고 성공 뒤 기기의 토큰·프로필 및 타로 식별자를 지웁니다. 기기 저장소 삭제에 실패하면 별도 경고합니다.

PostgreSQL 트랜잭션에서 계정을 잠가 삭제 상태로 표시하고 세션, 계정 연결·비밀번호 자격 증명, 프로필·일일 캐시, 대화·메시지, 기억·정정 이력·삭제 마커, 풀이와 근거 스냅샷, 타로, 생성 작업, 개발용 구매·권한을 제거합니다. 다른 사용자 및 공통 지식은 유지합니다. 계정의 불투명 식별자와 삭제 상태는 이후 쓰기를 차단하는 tombstone으로 남습니다. 진행 중 생성 작업의 완료 저장은 계정 잠금과 삭제 세대로 거절되며, 읽기 경로도 삭제 계정을 제외합니다.

구매 감사용 `purchase_transactions`는 계정 연결을 제거하고 공급자·거래 ID, 상품, 상태와 시각을 남깁니다. 거래 ID는 스토어에서 개인과 연결될 수 있으므로 **가명 처리이며 익명화가 아닙니다**. 구체적인 보존 기간, 환불 및 분쟁 처리, 실제 스토어와 연동한 삭제 정책은 출시 전에 정해야 합니다. 개발용 모의 거래는 연결된 생성 작업과 함께 삭제됩니다.

외부 모델에 이미 보낸 내용은 회수할 수 없고 공급자 데이터 보존 정책이 적용됩니다. 백업, 과거에 연결했던 외부 서비스, 사용자가 별도로 보관한 사본의 삭제는 이 API가 보장하지 않습니다. 사용자 첨부·원격 객체·개인 임베딩·별도 검색 캐시는 현재 지원하지 않습니다. 앞으로 추가하면 이 삭제 트랜잭션과 비동기 정리·실패 재시도에 연결하기 전에는 전체 삭제 지원으로 간주하지 않아야 합니다. Mem0를 사용한 적이 있다면 해당 서비스의 별도 삭제를 확인해야 합니다.

개발용 `DELETE /v1/dev/account/postgres-data`는 기존 호환 경로로 PostgreSQL 범위만 삭제하고 응답에 `complete_account_deletion: false`를 표시합니다. JSON 파일이나 별도 외부 저장소는 삭제하지 않습니다. 실제 PostgreSQL로 삭제·세션 해제·다른 사용자 격리·구매 분리·캐시 삭제·진행 중 쓰기 차단을 시험했습니다. 실제 스토어, 외부 모델, 백업과 기기 삭제는 별도 실환경 검증이 필요합니다.
