# 계정 데이터 삭제 기반

`persistence.Store.DeleteAccount`는 PostgreSQL 트랜잭션에서 계정을 잠그고 삭제 상태로 표시한 다음 세션, 계정 연결, 출생 프로필, 대화·메시지, 기억·이력, 풀이와 근거 스냅샷, 타로, 생성 작업, 열람 권한을 삭제합니다. 다른 사용자 및 공통 지식 자료는 삭제하지 않습니다. 계정의 불투명 식별자와 삭제 상태는 재생성을 막는 tombstone으로 남습니다. 구매 거래에는 상담 내용을 저장하지 않고 계정 연결을 제거하되 스토어 거래 ID와 상품·상태는 별도 보존합니다. 이는 가명 처리이며 완전한 익명화는 아닙니다. 실제 보존 기간, 분쟁·환불 처리와 삭제 정책은 출시 전 정해야 합니다.

계정별 직접 쓰기는 데이터베이스 가드가 삭제 계정에 대해 거부합니다. 진행 중인 작업은 실행 전 `deletion_generation`을 기록하고 결과 저장 시 `WithActiveAccount`에 전달해야 합니다. 이 함수는 계정 행을 삭제와 같은 방식으로 잠그고 세대가 다르거나 계정이 삭제됐을 때 쓰기를 거절합니다. 외부 모델 호출은 트랜잭션 밖에서 수행해야 합니다.

실제 PostgreSQL에서 삭제, 세션 무효화, 구매 계정 연결 제거, 늦은 쓰기 거부와 동시 작업 직렬화를 시험했습니다. 현재 API 삭제 엔드포인트 및 JSON 기반 풀이 저장소에는 연결되지 않았으며, 외부 객체 저장·임베딩·검색 캐시는 구현되지 않아 그 삭제 역시 미구현입니다. 운영 데이터에는 이 경로만으로 완전한 개인정보 삭제가 보장되지 않습니다.

개발용 PostgreSQL 모드에서는 인증된 사용자가 `DELETE /v1/dev/account/postgres-data`를 호출할 수 있습니다. 서버는 본문의 사용자 ID를 사용하지 않고 세션의 사용자만 삭제하며 PostgreSQL 세션을 무효화합니다. 응답은 `postgres_data_deleted_only` 및 `complete_account_deletion: false`로 범위를 명시합니다. 기존 JSON 풀이 파일이나 외부 저장소는 그대로 남을 수 있으므로 이 경로를 일반 계정 탈퇴 기능으로 노출하지 마세요. 정적 토큰 모드에서는 503으로 거부합니다.
