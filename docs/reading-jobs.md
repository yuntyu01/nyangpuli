# 비동기 풀이 작업

PostgreSQL 모드에서 `POST /v1/reading-jobs`에 인증 Bearer 토큰과 `Idempotency-Key` 헤더를 보내고 기존 풀이 요청과 같은 `domain`, `variant`, `input`, `use_memory` JSON을 보낸다. 서버는 사용자와 요청 키로 고유한 작업을 기록하고 `202`와 작업 ID를 반환한 다음 모델 호출을 시작한다. 동일 키·동일 입력의 재요청은 같은 작업을 반환하고 입력이 다르면 충돌한다. 응답이 연결 중단으로 유실됐으면 같은 인증과 `Idempotency-Key`로 `GET /v1/reading-jobs`를 호출해 ID와 상태를 복구할 수 있다. 또는 `GET /v1/reading-jobs/{id}`로 조회한다. 다른 사용자 작업은 조회할 수 없다.

`pending_or_interrupted`는 이 서버 프로세스에서 작업 중이거나 서버 중단 등으로 결과를 확인할 수 없는 상태다. `ready`에는 무료 요약만 포함된다. `failed`는 검증되지 않은 응답이고, `unknown`은 공급자 호출 결과나 비용이 불확실한 상태다. 이 상태에서 자동 재호출하지 않는다. 모델 호출 도중 요청 연결이 끊겨도 같은 서버 프로세스는 최대 2분 동안 계속한다. 서버 프로세스 재시작 후 작업을 재개하거나 불확실한 결과를 정산하는 워커는 아직 없다. 장기 실행 상태를 완료로 추정하지 않는다.

실제 공급자 API를 설정하지 않으면 시작은 503이며 내용을 꾸며내지 않는다. 이 API는 `DATABASE_URL`과 검증된 DB 세션 인증이 필요하고 JSON 실험 모드에는 제공되지 않는다. 실제 모델 응답 품질과 비용은 별도로 평가해야 한다.

## 상세풀이 작업과 재연결

PostgreSQL 모드에서 인증된 사용자는 `POST /v1/readings/{id}/detail-jobs`로 해당 풀이의 상세 생성을 시작하고, `GET /v1/readings/{id}/detail-jobs`로 같은 작업 상태를 다시 확인한다. 사용자·풀이마다 하나의 작업을 예약하므로 별도의 요청 키 없이 반복이나 동시 요청이 같은 작업을 반환한다. 응답은 작업 ID와 `pending_or_interrupted`, `ready`, `failed`, `unknown`, `invalidated` 또는 `not_started` 상태만 제공한다. 상태 응답에는 요약·상세 내용과 고정 근거가 들어가지 않는다. 준비된 후에도 `GET /v1/readings/{id}`가 당시 열람 권한을 다시 확인한 뒤 상세를 반환한다. 권한이 없으면 402이며 다른 사용자의 풀이와 삭제된 계정은 조회할 수 없다.

예약 직전 권한 확인은 계정 잠금 트랜잭션에서 환불·삭제와 직렬화한다. 환불이 모델 호출 시작 전에 확인되면 호출하지 않고 `not_started`로 기록한다. `not_started`는 공급자 호출이 없었던 경우에만 사용하며, 이후 새 권한이 생겼을 때 사용자가 명시적으로 다시 POST하면 같은 작업을 한 번만 시작한다. 호출이 이미 시작된 뒤에는 발생한 비용을 되돌릴 수 없지만, 환불 후에는 상세 조회와 상태 조회가 차단된다. 계정 삭제나 기억 정정·삭제가 실행 중 작업의 결과 재저장을 막는다. 요청 연결이 끊겨도 현재 프로세스의 작업은 최대 2분간 계속한다. 서버가 중단된 뒤 결과나 비용이 불확실한 작업을 자동 재호출하거나 완료로 추정하지 않는다. 향후 실제 스토어 권한 갱신도 동일한 계정 행 잠금을 사용해야 환불과 결과 조회가 직렬화된다. 이미 외부로 전송한 데이터는 회수할 수 없다. 실제 스토어 권한 검증과 불확정 비용 정산은 아직 구현되지 않았으며, 현재 권한 경로는 명시적으로 활성화한 개발 모의 구매에 한정된다.
