# 원본 엔진 회귀시험과 이후 Go 이식

현재 사주 계산은 Go가 OhMySaju의 고정된 TypeScript/Node 빌드를 호출한다. 이 문서와 시험은 나중에 Go 구현으로 교체할 때 **같은 입력에서 같은 계산 결과가 나오는지** 확인하기 위한 것이다. 원본 엔진과 일치한다는 것은 독립적으로 계산이 옳다고 증명하거나 미래 사건을 맞힌다는 뜻이 아니다. 아직 Go 계산 엔진은 구현하지 않았다.

## 지금 실행할 수 있는 시험

저장소 루트에서 사주 원본을 설치한 다음 실행한다. 시험 자체는 네트워크와 LLM을 사용하지 않는다.

```bash
bash scripts/setup-saju.sh
node scripts/engine-regression.mjs
```

입력은 `fixtures/engine-regression-inputs.json`, 관측 기준값은 `fixtures/engine-regression-golden.json`에 있다. 기본 모드는 기준값을 변경하지 않고 원본 어댑터를 실제로 실행하여 비교한다. 입력 파일 해시, 원본 커밋, 의존성 잠금 파일, 빌드 파일 트리, 어댑터 해시가 달라지면 조용히 통과시키지 않는다.

새 기준값 기록은 다음과 같이 **명시적으로** 실행한다. 원본 계산 결과가 기준이 되므로, 불일치를 없애려고 이 명령부터 실행하면 안 된다. 원본 버전이나 계산 정책을 바꿀 때 변경 이유와 전후 결과를 검토하고, 이전 기준도 버전 관리에 남긴다. `--record`는 이유 없이 실행되지 않으며, 교체된 출처 메타데이터와 이유, 계산 결과가 바뀐 사례 목록을 `provenance_history`에 남긴다.

```bash
node scripts/engine-regression.mjs --record --reason "변경 이유"
```

출처 검사가 실패해도 20개 계산 결과 비교는 계속 실행하고 보고서에 `provenance_failures`와 `failed`를 따로 표시한다. 둘 중 하나라도 있으면 종료 코드 1이다. 검사를 끄는 옵션은 없다.

## 고정한 20개 입력

| 범위 | 개수 | 확인할 내용 |
|---|---:|---|
| 일반 명식과 지정일 일진 | 1 | 일진은 출생 IANA 시간대의 정오를 대표 시각으로 사용 |
| 자정 양쪽 | 2 | `civilMidnight` 정책에서 23:59와 다음 날 00:00 |
| 윤일과 잘못된 평년 날짜 | 2 | 2024-02-29 수용, 2023-02-29 거부 |
| 입춘 경계 양쪽 | 2 | 2024-02-04 서울 17:26과 17:27의 연주·월주 |
| 서울 1908년 표준시 도입 | 3 | 과거 LMT 오프셋 30,472초, 이후 30,600초, 전환으로 없는 시각 거부 |
| 서울 1961년 시간대 변경 | 3 | 30,600초에서 32,400초로 변경, 전환으로 없는 시각 거부 |
| 뉴욕 DST 시작·종료 | 5 | 시작 전후 정상 시각, 없는 시각, 중복 시각 거부, 종료 후 정상 시각 |
| 잘못된 시간대·출생시간 미상 | 2 | 알 수 없는 IANA 시간대 거부, 미상 시간을 임의 정오로 대체하지 않음 |

원본의 입춘 추정 시각은 `2024-02-04T08:26:49.630Z`, 서울 시각으로 `17:26:49.630`이다. 원본 `src/timing/calculate-saju-timing.test.ts`와 계산 결과의 `audit.evidence.lichun`에서 확인했다. 현재 어댑터는 시·분만 받으므로 가장 가까운 양쪽 분을 검사한다. **정확한 초·밀리초의 경계 포함 규칙은 이번 20개 시험에 포함되지 않는다.** 원본이 기록한 1,500,000밀리초의 천문 소스 불확실성 및 경계 경고도 무시하지 않는다.

기준값에는 13개 성공 결과와 7개 기대 오류가 있다. 오류는 `INVALID_DATE`, `NONEXISTENT_LOCAL_TIME`, `AMBIGUOUS_LOCAL_TIME`, `UNKNOWN_TIME_ZONE`, 시간 미상에 대한 어댑터 오류 코드로 비교한다. 오류 문장 자체는 비교하지 않는다.

## 무엇을 비교하는가

실제 계산 필드와 원본 출처 메타데이터를 분리한다.

- **명식 계산:** 연·월·일·시주 전체, 간지 순번, 천간·지지 속성, 십성·지장간·오행·음양·명식 내 관계 사실.
- **시간 계산:** 양력·한국 음력 날짜, 민간시각, UTC 순간, IANA 시간대, 초 단위 오프셋, DST와 시간 선택 정책.
- **일진:** 대표 시각·날짜·연월일주·십성·원국과 일진 간 관계 사실.
- **경고:** 경고 코드. 설명 문장의 표현 차이는 비교하지 않는다.
- **출처 메타데이터:** 원본 커밋, 기록 당시 Node·pnpm, 의존성 잠금 해시, 빌드 트리 해시. 미래 Go 후보가 TypeScript 빌드 메타데이터를 흉내 낼 필요는 없다.

객체 키 순서는 비교에 영향을 주지 않고, 배열 순서와 숫자는 정확히 비교한다. 불일치 시 첫 번째 다른 필드 경로를 출력하고 종료 코드 1을 반환한다. 구조 변경이나 수치 허용 오차가 필요하면 비교 규칙을 별도로 검토해야 한다.

## 미래 Go 후보 연결 계약

후보 실행 파일은 기존 `adapters/ohmysaju/bridge.mjs`와 같은 단일 요청 프로토콜을 구현하면 된다.

1. stdin에서 기존 `{question,birth,date?}` JSON 한 개를 받는다.
2. 성공 시 stdout에 `{chart,daily?}` 형태의 JSON 한 개를 출력하고 종료 코드 0을 반환한다.
3. 실패 시 stderr에 `{"error":"동일한_오류_코드","message":"설명"}` JSON 한 개를 출력하고 0이 아닌 종료 코드를 반환한다. 로그를 JSON 스트림에 섞지 않는다.

```bash
# 아래 실행 파일은 앞으로 구현할 후보의 예시 경로이며 현재 제공하지 않는다.
node scripts/engine-regression.mjs --candidate ./bin/nyang-saju-go

# 인수가 필요하면 하나씩 전달한다. shell 문자열로 실행하지 않는다.
node scripts/engine-regression.mjs --candidate node --arg adapters/ohmysaju/bridge.mjs
```

`--candidate`는 기준값만 읽고 덮어쓰지 않는다. `--record`와 동시에 사용할 수 없다. `spawnSync`의 별도 인수 배열과 `shell:false`를 사용하며 각 요청은 15초 이내로 제한한다.

## build_tree_sha256 불일치 조사 (2026-10-30)

이전 기록(f3980d2까지)은 `build_tree_sha256`가 golden `3019d2c9...`와 달라 실패했다. 원인을 항목별로 나눠 확인했다.

| 구분 | 확인 결과 |
|---|---|
| 원본 커밋 | 고정 커밋 `a8c0cf6`의 깨끗한 checkout. 차이 없음 |
| 의존성 잠금 | `pnpm_lock_sha256` 일치. `--frozen-lockfile` 설치 |
| 어댑터 | `adapter_sha256` 일치 |
| 빌드 환경(Node·pnpm·경로) | 로컬 Node 20.20.0·pnpm 10.20.0 빌드와, 새 `node:24.22.1-bookworm-slim` 컨테이너에서 golden과 같은 Node 24.22.1·pnpm 10.15.0으로 다른 경로(`/app`)에 빌드한 결과가 **같은 `cba59b85...`**. 같은 위치 재빌드도 바이트 동일. Node·pnpm 버전과 체크아웃 경로는 원인이 아님 |
| 산출물 | 38개 파일 수는 같음. esbuild가 번들한 `astronomy-engine`의 설치 경로를 JS 주석과 소스맵에 기록함을 확인. pnpm `node-linker=hoisted`는 `25623efe...`, 전역 가상 저장소는 사용자 홈 경로가 들어간 `aedc91f9...`가 되어 **설치 레이아웃이 바뀌면 계산 코드가 같아도 해시가 달라짐** |
| 계산 결과 | 출처 검사를 유지한 채 20개 사례를 비교하면 20/20 일치. 기존 golden의 `results`와 새 기록의 `results`는 완전히 같음 |

결론: golden 해시는 고정 커밋·잠금파일·표준 레이아웃으로 재현되지 않는 빌드 상태(기록되지 않은 설치 레이아웃 또는 별도 빌드 과정)에서 기록되었다. 당시 파일별 해시를 남기지 않아 어느 파일이 어떻게 달랐는지는 복원할 수 없다. 이는 확인한 사실이 아니라 남은 가능성이며, 위 실험에서 재현한 레이아웃 중에는 `3019d2c9...`와 같은 값이 없었다.

조치:

- `scripts/setup-saju.sh`가 `node-linker=isolated`, 전역 가상 저장소 끄기, `node_modules/.pnpm` 경로를 명시한다. 사용자 환경변수로 hoisted·전역 저장소를 강제해도 정규 해시가 나오는 것을 확인했다.
- 출처 메타데이터에 파일별 해시(`build_files`)와 번들된 의존성 경로(`bundled_dependency_paths`)를 추가했다. 다음 불일치 때 바뀐 파일을 바로 보고한다. 빌드 파일 하나를 변조하면 해당 파일 이름과 함께 실패하는 것을 확인했다.
- 계산 결과가 같음을 확인한 뒤 이유를 붙여 출처 메타데이터만 재기록했다. 이전 값은 `provenance_history`에 남아 있다.

이식 전에 분·초 경계, 모든 절입, 넓은 출생 연도·시간대 표본, 음력 및 출생시간 미상 지원 정책을 추가해야 한다. 독립적인 달력 자료와의 대조시험은 이 회귀시험과 별도로 유지해야 한다.
