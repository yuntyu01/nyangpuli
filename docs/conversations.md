# 연속 상담과 개인 기억

2026-10-30 추가. 기존에는 상담이 질문 하나를 받아 풀이 하나를 만드는 흐름이었다. 이제 PostgreSQL 모드에서 대화 세션을 이어 갈 수 있다. 스키마에만 있고 쓰이지 않던 `conversations`/`messages` 테이블을 사용하고, 기억은 기존 `memories` 테이블과 정정·이력·삭제 구조를 확장했다. Mem0나 벡터 DB는 쓰지 않는다. JSON 랩 모드에서는 503이다.

## API

| 경로 | 역할 |
|---|---|
| `POST /v1/conversations` | 새 대화. `{linked_reading_id?, subject?}`로 내 풀이 하나를 명시적으로 연결 |
| `GET /v1/conversations` | 내 대화 목록(최근 사용자 메시지 앞부분, 연결한 풀이 종류) |
| `GET /v1/conversations/{id}` | 메시지, 연결한 풀이, 요약의 반영 기준점(`summary.through_seq`, `current`) |
| `POST /v1/conversations/{id}/messages` | `{content}` + `Idempotency-Key`. 202와 함께 사용자 메시지·대기 중 답변을 돌려준다 |
| `POST /v1/conversations/{id}/links` | 대화 중에 풀이를 더 연결(최대 5개) |
| `DELETE /v1/conversations/{id}` | 대화·메시지·연결·요약 삭제. 확인된 기억은 남고 출처 메시지 연결만 끊긴다 |
| `GET /v1/memory/inferences` | AI 추정(미확정) 목록 |
| `POST /v1/memory/{id}/confirm` | 사용자가 맞다고 한 추정을 확인된 기억으로 전환. 아니면 `DELETE /v1/memory/{id}` |

답변은 서버 작업으로 생성되며 앱은 `GET /v1/conversations/{id}`로 상태를 확인한다. 같은 요청 키를 다시 보내면 저장된 같은 차례를 돌려주고 모델을 다시 부르지 않는다. 같은 키에 다른 내용은 409다. 한 대화에서 답변이 생성 중이면 다음 메시지는 409다. 3분이 지나도 끝나지 않은 답변은 `unknown`으로 표시하며 비용이 불확실하므로 자동 재호출하지 않는다.

## 답변 생성 시 구분해 넣는 정보

한 번의 생성 호출에 다음을 **서로 다른 항목**으로 넣는다(`internal/conversation/prompt.go`의 `CONTEXT_JSON`).

1. `current_user_message`: 이번에 답할 메시지.
2. `recent_messages`: 최근 원문. 요약이 다루지 않은 메시지는 모두 원문으로 넣는다. 요약이 늦어도 최신 메시지가 빠지지 않는다. 원문 상한(기본 24개)을 넘으면 빠진 구간을 `omitted_messages`로 알린다.
3. `conversation_summary`: 더 오래된 대화의 요약과 반영 기준점(`covers_through: msg:N`). 기억이 정정·삭제된 뒤의 요약은 `stale_ignored`로 쓰지 않는다.
4. `personal_memory`: 확인된 사실(`facts`)과 시점·대상·상황별 기록(`episodes`). AI 추정은 넣지 않는다.
5. `linked_results`: 사용자가 이 대화에 연결한 풀이. 연결 시점의 요약·입력·고정 근거를 복사하고 `subject`(self/other/pair)를 붙인다.

모든 항목에는 `msg:N`, `sum:N`, `mem:ID`, `link:ID` 형태의 ID가 있고 답변이 쓴 근거 ID를 기록한다.

## 응답 후 처리

- 같은 호출의 JSON 출력에 `memory_candidates`가 있다. 현재 사용자 메시지에서만 뽑는다.
- `user_stated`는 `quote`가 그 메시지에 그대로 있어야 한다. 없으면 코드가 `ai_inference`로 낮춘다.
- `ai_inference`(성격, 상대의 마음, 관계 전망 등)는 `confirmed=false`로 저장해 생성 문맥과 `GET /v1/memory`에 나오지 않는다. 사용자가 확인하거나 삭제한다.
- 모든 후보는 출처 메시지 ID(`source_message_id`)와 `message:<id>:<n>` 사건 ID를 가진다. 같은 메시지를 다시 처리해도 같은 ID라 중복되거나 이후 정정을 덮어쓰지 않는다.
- 요약은 요약 밖 메시지가 기본 12개 이상 쌓였거나 요약이 무효가 되었을 때만 별도 호출로 다시 만든다. 저장 시 다룬 마지막 메시지 번호와 당시 기억 세대를 기록하고, 생성 중 기억이 바뀌면 저장하지 않는다. 요약 실패는 재시도하지 않으며 다음 차례에는 원문으로 보충된다.

## 기억의 종류

| 종류 | 예 | 관리 |
|---|---|---|
| `fact` | 관계 상태, 연락 경계, 선호 | 같은 키는 가장 최근에 말하거나 정정한 값이 유효. 사용자가 말한 시각을 기준으로 한다 |
| `episode` | 사건, 감정, 해 본 방법과 결과, 바람 | 서로 대체하지 않는다. 시점·대상(`subject`)·상황(`situation`)과 함께 모두 보존 |

“다시 만나고 싶다”(혼자 있는 밤)와 “연락은 부담스럽다”(상대 SNS를 본 뒤)는 둘 다 남는다. 상담 지침은 반대되는 기록을 하나로 합치거나 성격·진심을 단정하지 말라고 한다. 이 지침의 준수 여부는 모델 평가로 확인해야 하며 코드로 보장되지 않는다.

## 정정·삭제가 되살아나지 않게 하는 장치

- 정정·삭제·확인은 계정의 기억 세대를 올린다. 이전 세대의 요약은 쓰지 않고 다시 만든다. 재생성 입력에는 현재 기억이 들어가고 “기억과 메시지가 다르면 기억을 따르라”고 지시한다.
- 메시지에서 나온 기억을 삭제하면 `memory_suppressions`에 (메시지, 키)가 남는다. 같은 메시지에서 같은 키를 다시 저장하려 하면 거부되고, 그 메시지는 이후 답변 문맥과 요약 입력에서 “내용 생략”으로 바뀐다.
- 기억 삭제는 대화 메시지를 지우지 않는다. 대화 원문까지 지우려면 대화를 삭제한다. 이미 외부 모델 공급자에게 보낸 내용은 회수되지 않는다.

## 시험

`internal/conversation/*_test.go`, `internal/api/conversations_test.go`. 실제 PostgreSQL에서 모의 모델로 실행한다. 확인한 것: 요약 지연 시 최신 원문 유지와 빠진 구간 보고, 정정 후 요약 무효·재생성, 삭제된 기억의 출처 메시지 생략과 재저장 거부, 반대되는 감정 기록의 공존, AI 추정의 미확정 저장, 요청 키 재사용, 동시 답변 차단, 중단된 답변의 `unknown` 처리, 다른 사용자의 대화·풀이 접근 차단, 계정 삭제 후 쓰기 거부. 모의 모델 시험은 답변 품질을 평가하지 않는다.
